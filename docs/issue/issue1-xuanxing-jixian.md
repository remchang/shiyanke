## 背景
实验要求先比较 RealWorld 规范路线和 Ghost 路线再动手，不能看哪个 star 多就用哪个。

## 两条路线对比
- **Ghost 路线**：成熟的成品博客系统，自带编辑器、标签、会员、评论、主题机制和 SQLite 存储，二次开发边界放在「自定义主题 + Content API」，课堂 2 学时内能把时间花在改造而不是重写基础能力上。
- **RealWorld 路线**：它是一套 API/E2E 规范，不是可直接运行的应用，需要先选定一个合规实现、固定 commit，再自己补齐前端和后台，工作量明显更大。

## 决定
选 **Ghost 路线**。固定版本：Ghost 6.10.3（npm 包），Node.js v22.23.2，npm 10.9.8，Git 2.54，数据库 SQLite（随 Ghost 本地安装）。

## 风险
1. Ghost 官方 CLI 不支持 Windows 本地安装，本机又没有 WSL/Docker → 用 npm 包直接启动的手动方案，安装步骤写进 scripts/anzhuang.ps1，保证别人能复现。
2. C 盘空间不足 → 运行时依赖放 D 盘，仓库里用 junction 链接。
3. Content API 只能读公开内容，管理密钥不能进前端。

## 6 条验收场景
1. 管理员能在 /ghost 登录并发布一篇带标签的文章，前台能看到。
2. 普通会员能注册/登录，密码错误时有明确提示。
3. 会员能在文章详情页发表评论，匿名访客看不到评论输入框（按后台权限设置）。
4. 中文关键词能在前台搜索框命中标题或正文，结果可以点进文章。
5. 搜索一个不存在的词时，出现友好的「无结果」提示和标签推荐。
6. 停止再启动 Ghost 后，文章、标签、评论都还在；管理端导出的内容文件可以恢复。
