## 分层说明

1. **表现层（主题）**：全部页面模板与静态资源，二次开发主要集中在这一层。
2. **功能层（本地搜索增强）**：自主功能放在主题层实现，只读公开密钥，不碰管理密钥。
3. **服务层（Ghost 内容与会员服务）**：Ghost 提供的 Content API（公开只读）、Admin API（写操作）、Members API（会员与评论）。
4. **数据层（SQLite）**：单文件数据库，备份就是把 `ghost-dev.db` 复制走，恢复就是复制回来（或从管理端导出/导入 JSON）。

## 关键请求链路（以搜索为例）

1. 访客打开 `/sousuo/`，主题渲染搜索页模板，`page-sousuo.hbs` 输出页面骨架和 `#sousuoPeizhi` 配置节点。
2. `bendi-sousuo.js` 读取配置里的站点地址和 Content API 只读密钥。
3. 首次搜索时通过 Content API 拉取全部公开文章（标题/摘要/正文纯文本），之后在浏览器本地缓存。
4. 本地匹配排序：标题命中 > 摘要命中 > 正文命中；结果中关键词用 `<mark>` 高亮。
5. 最近搜索存 `localStorage`（最近 8 条，去重、新的在前）。
6. 无结果时显示兜底提示 + 由主题 `#get tags` 服务端渲染的标签墙。

## 为什么把功能放在主题层

- 不改 Ghost 核心，升级 Ghost 只需重新上传主题；
- Content API 只读密钥本就被设计为可放在前端；
- 便于课堂演示和可重复测试（`tests/zidong/ceshi.js` 直接断言该逻辑）。
